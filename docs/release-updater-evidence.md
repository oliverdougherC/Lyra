# PLA-159 update and schema evidence

Status: implementation prepared for review; **installed N→N+1 and rollback acceptance remain open**. This document is source-level evidence, not a claim that a signed/notarized public beta or a successful installed update exists. The release ledger records the final candidate SHA, version and artifact hashes.

## Implemented contract

The supported `tauri-plugin-updater` 2.11 client performs update selection, HTTPS download, mandatory minisign artifact verification and app replacement. Only native custom IPC commands are allowed; renderer plugin installation commands are not granted. The persisted public key is `src-tauri/updater-public-key.txt`. The private half is retained separately by the release owner and never bundled. No replacement script, automatic launch check, automatic download, or background daemon exists.

Settings displays the local current version/channel, not-checked versus up-to-date, time of the last explicit check, release notes, progress, cancellation/errors, verified-download readiness, installation and an explicit restart button. Checks target the repository Pages `/beta/latest.json` or `/stable/latest.json`; internal 0.1.0 and prerelease versions use beta. The plugin's default semantic version comparator rejects non-increasing versions. Beta feed publication does not use GitHub's latest-release endpoint.

Alongside the Tauri static-feed fields, the publisher emits:

```json
{"lyra":{"bundleIdentifier":"com.lyra.desktop","architecture":"aarch64","schemaMin":0,"schemaMax":45,"size":123456}}
```

`schemaMax` is derived from migrations by publisher tooling (45 at this revision), and `size` is the exact signed updater archive byte count. Native checks validate platform, bundle contract, pinned GitHub repository asset URL, declared size, and the **actual authenticated backend profile schema** at check and again before installation. TLS protects feed transport; Tauri verifies the downloaded archive's signature against the embedded key. The additional metadata is not a separate signed-envelope protocol. Native validation binds the verified archive’s `lyra-release.json` version/build/schema/architecture to the selected feed, then checks the actual signed Info.plist and the executable’s Apple Silicon Mach-O header. Replaying an older legitimately signed archive under a newer unsigned feed version is refused. Archive paths/links are confined to Lyra.app, duplicate/special entries are rejected, and expanded contents are capped at 2 GiB.

Downloads stay in the supported plugin's in-memory staging buffer. The application accepts archives up to 512 MiB, checks reported/observed size, supports cancellation by dropping the download future, and requires six times the archive size (or validated expanded size before replacement) plus 512 MiB free on both temporary and application volumes. Retry starts cleanly; partial download resume is not implemented. This is not an 8 GB memory acceptance result, and compressed size alone cannot prove extraction-space requirements. The signed publisher artifact inventory remains part of the gate.

Before install the UI refuses outstanding settings writes, dirty settings, draft saves and writing conflicts (including saves still pending after editor unmount). The modal prevents further UI edits during replacement. Active work is explicitly disclosed as interrupted, and the native lifecycle guard prevents backend bootstrap/retry/import from racing update shutdown. Owned backend/helpers must stop successfully before installation. Failed replacement attempts resume the backend where possible; successful replacement waits for the user to select Restart. The updater never replaces the student data directory, Keychain, downloaded helpers or workspace files.

## Future-schema refusal and migration recovery

`assert_schema_compatible()` reads the real SQLite schema read-only, including committed WAL data. It runs before connection WAL/hardening setup and at the start of both contributor and packaged lifespan, before import recovery, directory setup, storage recovery and backfill. `migrate()` independently refuses future versions. The message directs the user back to the newer app or a separately restored pre-migration copy; no downgrade is attempted.

For an existing database with pending migrations, migration creates a new private `migration-backups/schema-V-UUID/` directory beside the database before applying the first SQL statement. It contains an SQLite backup verified with integrity check and schema version, matching copies of the active profile's `uploads/` and `text/`, and a SHA-256 file receipt. Files and directory entries are synced before migration. Failure to create or verify the snapshot stops migration and leaves the original schema untouched. Original sources and extracted text are copied using owned no-follow reads. Drafts, study state, source revisions/snapshots, quotations and settings are in SQLite. Models/caches are regenerable; Keychain and fallback credential material stay in the original profile and are not copied into this migration receipt. External workspace files are not migrated by SQL and are not part of this snapshot.

Returning to an older binary after a forward schema change requires restoring compatible data separately; merely reinstalling an older DMG will be refused. Keep both the current profile and the snapshot. The snapshot's database/uploads/text layout can be selected by the existing import workflow; the full native backup/restore workflow is documented separately and preserves the prior profile during restoration. Migration snapshots are **not** full credential backups and are not automatically pruned. Before the supported plugin can move the original bundle, Lyra uses macOS ditto to retain a complete prior app in its separate durable update-recovery directory, verifies its code signature/designated bundle identity, compares all copied file SHA-256 hashes and symlink targets with the original (including frozen sidecar resources), and syncs the copy. Codesign and ditto use owned-process groups with 30-second and 120-second deadlines. This survives the plugin’s temporary-backup cleanup on failed replacement. The Settings and startup-error recovery actions reverify and reveal the retained app in Finder: quit the current single-instance app, then open the prior app. There is no automatic old-binary startup supervisor; use this explicit recovery and a compatible data snapshot when needed. Do not overwrite the only data copy.

## Executed evidence

- Three initial regression failures on the baseline: `connect()` accepted future schema and created sidecars; `migrate()` accepted future schema; upgrading an existing database produced no backup.
- Backend focused tests cover byte-preserved refusal before connect effects, independent migration refusal, contributor/packaged lifespan refusal before recovery/writes, verified old-schema/model preservation, backup failure before SQL mutation, and original/text hash preservation after deleting the source original.
- Migration upgrade/idempotence suite passes through every numbered historical schema. The health endpoint regression verifies actual profile version rather than reporting compiled schema.
- Native unit tests cover wrong architecture/bundle/schema/origin/size rejection, insufficient disk, beta/stable channel selection, actual Intel executable/corrupt archive rejection, archive link confinement, and old signed-archive identity replay refusal. The supported plugin compiles with the integrated lifecycle wrappers. The publisher verifier uses the same maintained minisign verifier/public key and has actual matching-key, corrupt-payload and unrelated-key signed fixture regressions.
- Frontend tests cover no network check/download at mount, explicit checking, settings-dirty refusal, pending writer preservation, failed local status read, and restart availability after a successful install whose status refresh fails. Existing save-engine regressions remain passing.
- Focused Python Ruff, frontend ESLint and TypeScript checks pass; integrated exact counts/build evidence belong in the final ledger.
